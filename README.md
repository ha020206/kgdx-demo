# 판정 시연 · 오개념

학생이 같은 개념을 묻는 두 문제에서 같은 오개념의 선지를 고르고 확신했을 때, 시스템이 **규칙으로 오개념을 판정 → 지식그래프에서 근거 찾기 → LLM으로 피드백 만들기**까지 가는 과정을 한 슬라이드씩(1~15) 보여 주는 화면입니다. 시연 영상 녹화와 휴대폰 시연에 씁니다.

## 실행

### 1. 그냥 열기 (가장 간단)

`index.html`을 더블클릭하면 브라우저에서 열립니다.

### 2. 로컬 서버로 열기

PowerShell에서 아래를 실행합니다.

```powershell
cd -LiteralPath "C:\Users\usr\Desktop\[26-2] 대학원\연구실\[26-2] RAG\시연용 영상 제작\kgdx-demo"
python -m http.server 8000
```

브라우저에서 <http://localhost:8000> 을 엽니다. 끌 때는 PowerShell 창에서 `Ctrl + C`를 누릅니다.

- 폴더 이름에 `[26-2]`처럼 대괄호가 있어서 `cd`에 `-LiteralPath`를 붙여야 합니다. 없으면 PowerShell이 `[ ]`를 와일드카드로 읽어 "지정한 와일드카드 문자 패턴이 잘못되었습니다" 오류가 납니다.
- VS Code에서 이 폴더를 열어 둔 상태라면, 터미널(`` Ctrl + ` ``)이 이미 이 폴더에서 열리므로 `cd`는 건너뛰어도 됩니다.

- 특정 슬라이드부터 열려면 주소 끝에 `?step=번호`를 붙입니다. 예: `http://localhost:8000/?step=9`, `index.html?step=15`
- 영상 녹화는 브라우저 전체 화면(`F11`), 1920×1080 기준으로 맞춰 두었습니다.

### 왜 HTML 두 개가 아니라 `data.js`인가

HTML 파일은 다른 HTML에 "변수 파일"로 불러올 방법이 `fetch`뿐인데, `fetch`는 `index.html`을 더블클릭해서 열면(`file://`) 브라우저가 막습니다. `<script src="data.js">`는 더블클릭과 GitHub Pages 양쪽에서 모두 동작합니다.

### 한 곳만 고치면 모든 곳에 반영

같은 내용(오개념 이름, 정답, 교과서 쪽 등)은 `data.js`에 **한 번만** 적혀 있고, 다른 글에서는 `{이름표}`로 불러 씁니다. 원래 값을 고치면 그 이름표를 쓴 설명 글, LLM 입력 칸, 그래프 노드, 피드백이 모두 함께 바뀝니다.

| 이름표 | 값을 가져오는 곳 (여기만 고치면 됨) | 지금 값 |
|---|---|---|
| `{문제1.번호}` `{문제1.고른번호}` `{문제1.고른답}` | `SLIDE_1.problem` | 1, ①, 아무것도 말하지 않는다 |
| `{문제1.정답번호}` `{문제1.정답}` `{문제1.확신도}` | `SLIDE_1.problem` | ③, 다솜, 확실해요 |
| `{문제1.오개념}` `{문제1.문제}` `{문제1.코드}` | `SLIDE_1.problem` (오개념은 고른 선지의 `mc`) | 삭제 뒤 번호 고정, … |
| `{문제2.…}` | `SLIDE_4.problem` (칸 이름은 문제1과 같음) | |
| `{피드백문제.…}` | `SLIDE_15.problem`이 가리키는 문제 | 지금은 문제 2 |
| `{오개념.이름}` `{오개념.설명}` | `SLIDE_3.misconceptions` 중 이번 판정의 오개념 | 삭제 뒤 번호 고정 |
| `{오개념.믿음확인질문}` `{오개념.실행반례}` | 같은 오개념의 카드 칸 | |
| `{정개념.이름}` | `SLIDE_9.graph`의 정개념(개념) 노드 `title` | 항목 삭제하기 |
| `{정개념.설명}` | 같은 노드의 `definition` | ‘(n)번째 항목을 (리스트)에서 삭제하기’를 하면 … |
| `{교과서쪽}` | `SLIDE_13.pages` | 102~103쪽, 104~105쪽 |
| `{판정결과}` | `SLIDE_8.result` | 오개념 |

- **조사 자동**: 이름표 바로 뒤에 `을/를`, `이/가`, `은/는`, `과/와`, `으로/로`처럼 둘 다 쓰면 받침에 맞는 쪽이 골라집니다.
  예: `"「{문제1.고른답}」을/를 고르고"` → 「아무것도 말하지 않는다」를 고르고. 정답이 "다솜"으로 바뀌면 「다솜」을.
- 이름표를 잘못 쓰면 화면에 `{잘못쓴이름}`이 그대로 보이니, 그걸 보고 고치면 됩니다.
- 그래프의 선지·오개념·교과서 노드 글자도 문제, 오개념, 쪽에서 자동으로 채워집니다.
- **피드백 문장은 예외입니다.** 정답 값은 `{피드백문제.정답}`으로 따라가지만, "어떤 항목을 지우면 리스트가 어떻게 되는지" 같은 설명은 LLM이 그 문제를 보고 쓴 문장이라 문제를 바꾸면 문장도 새로 씁니다(실제 시스템도 문제마다 LLM이 새로 씁니다).

### 글 쓰는 규칙

- 글은 `"큰따옴표"` 안에 씁니다. 글 안에 큰따옴표를 넣으려면 `\"`로 씁니다. 작은따옴표(‘ ’)와 낫표(「 」)는 그냥 써도 됩니다.
- `**글자**`처럼 별표 두 개로 감싸면 굵게 보입니다.
- 몇몇 칸에는 그 칸에서만 쓰는 이름표(`{번호}`, `{이름}`, `{쪽}` 등)가 있습니다. 칸 옆 주석에 적어 두었고, 지우지 말고 위치만 옮깁니다.
- 한 슬라이드에서 정한 내용이 뒤 슬라이드에도 나오면 주석에 "→ 슬라이드 N에도 나옴"이라고 적어 두었습니다. 예: 문제 2는 `SLIDE_4`에서 정하고 슬라이드 5~8과 15에 그대로 나옵니다.
- 쉼표(,)·따옴표·괄호가 빠지면 화면 아래에 빨간 안내가 나옵니다. `F12` → Console에 틀린 줄 번호가 나옵니다.
- 슬라이드의 개수와 순서(15개)는 화면 동작과 묶여 있어 바꾸지 않습니다. 글과 데이터만 바꿉니다.

### 자주 바꾸는 것

- **문제·선지**: `SLIDE_1.problem`(문제 1), `SLIDE_4.problem`(문제 2)
  - `code`는 한 줄이 블록 하나입니다. 줄 앞 공백 4칸은 들여쓰기 한 단계입니다.
  - 블록 안에서 `[이름]`은 드롭다운 칩, `(2)`는 값 칩, `([이름] 의 (2) 번째 항목)`은 값 블록이 됩니다.
  - `type`: `C` 정답, `T` 표적 오개념, `O` 다른 오개념, `D` 결손·미분류, `X` 그 외 답
  - 선지와 오개념은 `mc`(오개념 이름표, 예: `"MC-LIST-08"`)로 잇습니다.
- **학생 응답**: `problem.answer`의 `key`(선지 번호)와 `conf`(3 확실해요 / 2 조금 / 1 모름)
- **오개념 이름·설명·카드(믿음 확인 질문·실행 반례)**: `SLIDE_3.misconceptions`. 선지 아래 글, 판정 상자, 그래프 노드, LLM 입력 칸, 설명 글에 한꺼번에 반영됩니다.
- **정개념 이름·설명**: `SLIDE_9.graph`의 정개념(개념) 노드(`CPT-LIST-DELETE`)의 `title`, `definition`. 그래프 노드, LLM 입력 칸(정개념, 정개념 설명), 설명 글에 반영됩니다.
- **교과서 쪽**: `SLIDE_13.pages`. 그래프 교과서 노드, 쪽 칩, 피드백 맨 아래 줄, 설명 글에 반영됩니다.
- **그래프**: `SLIDE_9.graph`의 `nodes`, `edges`, `path`
  - 선지·오개념·교과서 노드의 글자는 문제·오개념·쪽에서 자동으로 채워집니다.
  - 노드 위치는 자동입니다. 넓은 화면에서 직접 정하려면 노드에 `x`, `y`를 씁니다.
- **LLM 입력**: `SLIDE_9.llmInput`. 값은 모두 이름표로 원래 자리에서 가져오므로 보통 고칠 필요가 없습니다. `from`이 그 칸이 채워지는 슬라이드를 정합니다(`item` 9, `card` 11, `concept` 12).
- **피드백**: `SLIDE_15.paragraphs`의 세 문단(위에서부터 믿음 확인 질문 → 실행 반례 → 정개념). 문단마다 `label`(소제목)과 `text`(문장)를 씁니다.
  - 문단은 위에서부터 0.7초 간격으로 차례로 나타나고, 마지막 문단은 옅은 초록 상자로 강조됩니다.
  - `**가**`는 굵게 보입니다.
  - 실제 시스템의 LLM 출력 검사 기준은 합쳐서 220자 이하, 3문장 이하이고, 쪽 번호·문항 번호·판정 이름을 쓰지 않는 것입니다. 지금 문장은 181자이고 원본 `proto/validate.py` 검사를 통과합니다.
- **색**: `index.html` 맨 위 `:root`(오답 `--wrong`, 정답 `--right`, 고를 때 `--pick` 등)

## 배포 (GitHub Pages)

`main` 브랜치에 push하면 GitHub Actions(`.github/workflows/static.yml`)가 저장소 전체를 GitHub Pages에 올립니다.

1. `data.js`(또는 `index.html`)를 고치고 로컬에서 확인합니다.
2. commit 후 `main`에 push합니다.
3. GitHub 저장소의 **Actions** 탭에서 "Deploy static content to Pages"가 초록색으로 끝나면(보통 1분 안팎) 배포된 주소에서 확인합니다.

배포 때문에 지키는 것:

- **주소는 상대 경로로 씁니다.** 배포 주소가 `https://<계정>.github.io/kgdx-demo/`처럼 하위 폴더라서, `/data.js`처럼 `/`로 시작하면 파일을 못 찾습니다.
- **파일 이름의 대소문자를 정확히 맞춥니다.** Windows는 `Data.js`와 `data.js`를 같게 보지만 GitHub Pages 서버는 다르게 봅니다.
- **`index.html`의 `<script src="data.js"></script>` 줄은 모양을 바꾸지 않습니다.** 배포할 때 이 줄을 찾아 `data.js?v=커밋번호`로 바꿉니다. GitHub Pages는 파일을 10분 정도 캐시해서, `data.js`만 고쳐 push하면 한동안 옛 `data.js`가 보일 수 있기 때문입니다. 저장소의 파일은 바뀌지 않고 배포본에만 적용됩니다. 이 줄을 못 찾으면 배포가 실패하며 알려 줍니다.
- `README.md`도 함께 배포되어 주소 뒤에 `/README.md`를 붙이면 보입니다.

## 실제 시스템과의 관계

원본 프로젝트 `연구및개발설계/kgdx_spec`의 코드와 비교해 점검한 결과입니다.

### 실제와 같은 것

- **판정 단위**: 원본 1-3·1-4는 같은 판정 단위(U2, 개념 `항목 삭제하기`)입니다. 두 응답을 함께 판정합니다. (`seed/item_sets.csv`)
- **판정에 쓰는 것**: 고른 답의 종류와 확신도만 씁니다(T3, T3). 문제 글과 고르지 않은 선지는 쓰지 않습니다. (`proto/judgement.py`)
- **판정 규칙**: 두 응답이 모두 표적 오개념이고 한 번 이상 확신했으면 판정표에서 오개념 칸입니다. 이어서 두 답의 오개념이 같은지 확인하고(다르면 판정 유보), 같으므로 오개념으로 판정합니다. LLM은 쓰지 않습니다. (`config/judgement_matrix_long.csv`, `config/rules.json`의 `mc_requires_same_card`)
- **그래프 경로(Q1)**: 선택지 → 카드 → 관련 개념 → 개념 → 설명 자료 → 학습 자료(교과서, 최대 2개) 순서로 찾고, 슬라이드 10~13이 이 순서입니다. (`proto/paths.py`)
- **LLM 입력 칸(문항·카드)**: 문항 번호, 판정 결과, 문제, 코드는 문항에서, 믿음 확인 질문·실행 반례는 오개념 카드에서 넣습니다. 카드의 '믿음'은 화면의 오개념 노드로만 보이고 LLM에는 넣지 않습니다. 교과서 쪽도 LLM에 넣지 않고 서버가 화면에 붙입니다. (`proto/llm_feedback.py`의 `_payload_review`, `_state_fields`)
- **피드백 쓰는 법**: 믿음 확인 질문 → 실행 반례(이 문항의 이름으로) → 정개념 순서로 2~3문장을 씁니다. 검사에 걸리면 한 번 더 생성하고, 그래도 안 되면 고정 문장을 씁니다. (`prompts/feedback_item_system.txt`, `config/feedback_validation.json`)

### 시연에서 다르게 보여 주는 것

- **채점 시점**: 실제 시스템은 학생이 모든 문제를 풀고 제출한 뒤 서버가 한꺼번에 판정합니다. 학생은 풀면서 ✕·✓를 보지 않습니다. 시연은 이해를 돕기 위해 문제마다 채점을 보여 줍니다.
- **선지 → 오개념 선**: 설계 경로의 "지시" 관계입니다. 화면에서는 선 위 글자를 뺐습니다. seed 그래프에는 선지 노드와 이 선이 없고, 선지가 어느 오개념과 연결되는지는 문항 데이터(`seed/items_seed.json` 선지의 `card_id`)에 적혀 있습니다. 시연은 이를 그래프 위에 그려서 보여 줍니다(원본 `proto/demo_case.py`도 같은 방식입니다). 글자를 다시 넣으려면 `SLIDE_9.graph.edges`의 첫 두 줄 `label`에 `"지시"`를 씁니다.
- **번호와 이름**: 원본 번호 1-3·1-4를 문제 1·2로 바꿨습니다. LLM 입력 칸 이름과 값은 한글로 보여 줍니다. 실제로는 `display_no: "1-4"`, `state: "MC"`처럼 들어갑니다.
- **오개념 이름**: 오개념 id(MC-LIST-08) 대신 원본 판정 대상 이름 「삭제 뒤 번호 고정」(T14)을 씁니다.
- **정개념 칸**: 설계서의 노드 유형 이름(정개념: 성취기준, 개념)에 맞춰 개념 노드를 "정개념"으로 부르고, 오개념 → 개념 선 글자도 "정개념"으로 씁니다(원본 관계 이름은 "관련 개념"). LLM 입력에는 정개념 노드의 **이름(정개념)과 설명(정개념 설명)**을 넣습니다. 지금 실제 코드(`_state_fields`)는 오개념 판정일 때 개념 이름과 **카드의 `correct_conception`**을 넣고 개념 설명(`definition`)은 넣지 않습니다. 실제 시스템도 시연처럼 바꾸려면 `_state_fields`의 MC 부분을 고쳐야 합니다.
- **피드백**: 문장은 미리 써 둔 것입니다. 실제 피드백 화면은 LLM 문장을 한 문단으로 보여 주지만, 시연은 세 문장에 소제목(믿음 확인 질문 · 실행 반례 · 정개념)을 붙여 문단으로 나눠 보여 줍니다. 각 문단은 슬라이드 11·12에서 LLM 입력에 들어간 근거(오개념 카드의 믿음 확인 질문·실행 반례, 정개념 노드의 이름·설명)를 이 문제에 맞게 풀어 쓴 것입니다.
- **선수 경로 생략**: 원본 판정 사례 P-05에 있던 1-1 선수 경로는 넣지 않았습니다.
