# 판정 시연 · 오개념

학생이 같은 개념을 묻는 두 문제에서 같은 오개념의 선지를 고르고 확신했을 때, 시스템이 **규칙으로 오개념을 판정 → 지식그래프에서 근거 찾기 → LLM으로 피드백 만들기**까지 가는 과정을 한 슬라이드씩(1~16) 보여 주는 화면입니다. 시연 영상 녹화와 휴대폰 시연에 씁니다.

## 실행

### 1. 그냥 열기 (가장 간단)

`index.html`을 더블클릭하면 브라우저에서 열립니다.

### 2. 로컬 서버로 열기

PowerShell에서 아래를 실행합니다.

```powershell
cd -LiteralPath "C:\Users\usr\Desktop\[26-2] 대학원\연구실\[26-2] RAG\시연용 영상 제작\kgdx-demo"
python -m http.server 8000
```

브라우저에서 <http://localhost:8000> 을 엽니다. 끌 때는 PowerShell 창에서 `Ctrl + C`를 누릅니다.

- 폴더 이름에 `[26-2]`처럼 대괄호가 있어서 `cd`에 `-LiteralPath`를 붙여야 합니다. 없으면 PowerShell이 `[ ]`를 와일드카드로 읽어 "지정한 와일드카드 문자 패턴이 잘못되었습니다" 오류가 납니다.
- VS Code에서 이 폴더를 열어 둔 상태라면, 터미널(`` Ctrl + ` ``)이 이미 이 폴더에서 열리므로 `cd`는 건너뛰어도 됩니다.

- 두 방법 모두 **인터넷 연결이 필요합니다**. 글꼴(Pretendard)과 그래프 라이브러리(vis-network)를 CDN에서 불러옵니다.
- 특정 슬라이드부터 열려면 주소 끝에 `?step=번호`를 붙입니다. 예: `http://localhost:8000/?step=9`, `index.html?step=15`
- 영상 녹화는 브라우저 전체 화면(`F11`), 1920×1080 기준으로 맞춰 두었습니다.

## 파일

| 파일 | 내용 | 고칠 때 |
|---|---|---|
| `data.js` | **화면에 보이는 모든 글자와 데이터**. 슬라이드 순서대로 `COMMON`, `SLIDE_1` ~ `SLIDE_15` 변수로 나뉨 | 내용을 바꿀 때는 이 파일만 |
| `index.html` | 화면 모양(CSS)과 동작(JS). 맨 위 `:root`에 색이 모여 있음 | 색·크기·움직임을 바꿀 때 |
| `.github/workflows/static.yml` | GitHub Pages 배포 | 안 고침 |

고친 뒤 브라우저를 새로고침(`F5`)하면 바로 반영됩니다.

### 왜 HTML 두 개가 아니라 `data.js`인가

HTML 파일은 다른 HTML에 "변수 파일"로 불러올 방법이 `fetch`뿐인데, `fetch`는 `index.html`을 더블클릭해서 열면(`file://`) 브라우저가 막습니다. `<script src="data.js">`는 더블클릭과 GitHub Pages 양쪽에서 모두 동작합니다.

### 한 곳만 고치면 모든 곳에 반영

같은 내용(오개념 이름, 정답, 교과서 쪽 등)은 `data.js`에 **한 번만** 적혀 있고, 다른 글에서는 `{이름표}`로 불러 씁니다. 원래 값을 고치면 그 이름표를 쓴 설명 글, LLM 입력 칸, 그래프 노드, 피드백이 모두 함께 바뀝니다.

| 이름표 | 값을 가져오는 곳 (여기만 고치면 됨) | 지금 값 |
|---|---|---|
| `{문제1.번호}` `{문제1.고른번호}` `{문제1.고른답}` | `SLIDE_1.problem` | 1, ②, 리본 본드 |
| `{문제1.정답번호}` `{문제1.정답}` `{문제1.확신도}` | `SLIDE_1.problem` | ④, 본드, 확실해요 |
| `{문제1.오개념}` `{문제1.문제}` `{문제1.코드}` | `SLIDE_1.problem` (오개념은 고른 선지의 `mc`) | 값이 쌓인다, … |
| `{문제2.…}` | `SLIDE_4.problem` (칸 이름은 문제1과 같음) | |
| `{피드백문제.…}` | `SLIDE_15.problem`이 가리키는 문제 | 지금은 문제 2 |
| `{오개념.이름}` | `SLIDE_3.misconceptions` 중 이번 판정의 오개념의 `name` | 값이 쌓인다 |
| `{오개념.설명}` | 같은 오개념의 `desc` | 변수가 여러 값을 동시에 가져서 … |
| `{오개념.믿음확인질문}` `{오개념.실행반례}` | 같은 오개념의 카드 칸 (지금 화면에는 안 씀) | |
| `{정개념.이름}` | `SLIDE_9.graph`의 정개념(개념) 노드 `title` | 변수 |
| `{정개념.설명}` | 같은 노드의 `definition` | 변수는 이름을 붙인 저장 공간이며 … |
| `{교과서쪽}` | `SLIDE_13.pages` | 102쪽 |
| `{판정결과}` | `SLIDE_8.result` | 오개념 |

- **조사 자동**: 이름표 바로 뒤에 `을/를`, `이/가`, `은/는`, `과/와`, `으로/로`처럼 둘 다 쓰면 받침에 맞는 쪽이 골라집니다.
  예: `"「{문제1.고른답}」을/를 고르고"` → 「리본 본드」를 고르고. 고른 답이 "리본"으로 바뀌면 「리본」을.
- 이름표를 잘못 쓰면 화면에 `{잘못쓴이름}`이 그대로 보이니, 그걸 보고 고치면 됩니다.
- 그래프의 선지·오개념·교과서 노드 글자도 문제, 오개념, 쪽에서 자동으로 채워집니다.
- **피드백 문장은 예외입니다.** 고른 답·정답·정개념 이름은 이름표로 따라가지만, "배터리를 100, 50, 80으로 차례로 정하면" 같은 설명은 LLM이 그 문제를 보고 쓴 문장이라 문제를 바꾸면 문장도 새로 씁니다(실제 시스템도 문제마다 LLM이 새로 씁니다).

### 글 쓰는 규칙

- 글은 `"큰따옴표"` 안에 씁니다. 글 안에 큰따옴표를 넣으려면 `\"`로 씁니다. 작은따옴표(‘ ’)와 낫표(「 」)는 그냥 써도 됩니다.
- `**글자**`처럼 별표 두 개로 감싸면 굵게 보입니다.
- 몇몇 칸에는 그 칸에서만 쓰는 이름표(`{번호}`, `{이름}`, `{쪽}` 등)가 있습니다. 칸 옆 주석에 적어 두었고, 지우지 말고 위치만 옮깁니다.
- 한 슬라이드에서 정한 내용이 뒤 슬라이드에도 나오면 주석에 "→ 슬라이드 N에도 나옴"이라고 적어 두었습니다. 예: 문제 2는 `SLIDE_4`에서 정하고 슬라이드 5~8과 16에 그대로 나옵니다.
- 쉼표(,)·따옴표·괄호가 빠지면 화면 아래에 빨간 안내가 나옵니다. `F12` → Console에 틀린 줄 번호가 나옵니다.
- 슬라이드의 개수와 순서(16개)는 화면 동작과 묶여 있어 바꾸지 않습니다. 글과 데이터만 바꿉니다.

### 자주 바꾸는 것

- **문제·선지**: `SLIDE_1.problem`(문제 1), `SLIDE_4.problem`(문제 2)
  - `code`는 한 줄이 엔트리 블록 하나입니다. 위아래로 붙여 쌓이고, 줄 앞에 공백 4칸을 넣으면 한 단계 들여씁니다.
  - 블록 안에서 `[단어]`는 드롭다운(▾), `(리본)`은 옅은 노란 입력 칸, `([단어] 값)`은 보라 값 블록이 됩니다.
  - 블록 색은 낱말로 정해집니다: '시작하기' → 시작(초록, ▶), '말하기' → 생김새(빨강), '정하기' → 자료(보라, 끝에 ?). 색 값은 `index.html` 맨 위 `--hat`, `--var`, `--looks`, `--field`.
  - `type`: `C` 정답, `T` 표적 오개념, `O` 다른 오개념, `D` 결손·미분류, `X` 그 외 답. 마지막 선지는 늘 '그 외의 답'.
  - 선지와 오개념은 `mc`(오개념 이름표, 예: `"MC-VAR-01a"`)로 잇습니다.
- **학생 응답**: `problem.answer`의 `key`(선지 번호)와 `conf`(3 확실해요 / 1 확실하지 않아요)
- **확신도 보기**: `COMMON.confidence` (지금은 확실해요·확실하지 않아요 두 개)
- **오개념 이름·설명**: `SLIDE_3.misconceptions`의 `name`, `desc`. 판정 상자, 그래프 노드, LLM 입력 칸(오개념, 오개념 설명), 피드백 상자, 설명 글에 한꺼번에 반영됩니다. 채점(슬라이드 3·6)에는 정답·오답만 보이고 오개념은 나오지 않습니다.
- **정개념 이름·설명**: `SLIDE_9.graph`의 정개념(개념) 노드(`CPT-VAR`)의 `title`, `definition`. 그래프 노드, LLM 입력 칸(정개념, 정개념 설명), 설명 글, 피드백에 반영됩니다.
- **교과서 쪽**: `SLIDE_13.pages`. 그래프 교과서 노드, LLM 입력 칸(학습 자료), 피드백 상자(교과서 다시 보기, 피드백 문단), 설명 글에 반영됩니다.
- **그래프**: `SLIDE_9.graph`의 `nodes`, `edges`, `path`
  - 찾아가는 길(`path`)의 노드는 큰 원입니다. 원 안에는 `SLIDE_9.nodeText`의 글자(문제1 ②, 오개념, 정개념, 학습 자료), 원 아래에는 이름(값이 쌓인다, 변수, 102쪽)이 붙습니다.
  - 길에 없는 주변 노드(리스트, 함수, 처음 값을 기억한다, 118쪽 등)는 작은 원과 이름만 보이고, 종류 색(오개념 빨강, 정개념 파랑, 학습 자료 초록)을 겨우 알아볼 만큼 아주 연하게 칠합니다. 이 연한 색은 `index.html`의 `KIND`에서 `faintBg`, `faintBorder`입니다.
  - 선에는 글자를 쓰지 않습니다. 원 색(회색·빨강·파랑·초록)은 `index.html`의 `KIND`에 있습니다.
  - 선지·오개념·교과서 노드의 이름은 문제·오개념·쪽에서 자동으로 채워집니다.
  - 길 노드 위치는 자동이고, 주변 노드는 `x`, `y`로 정합니다. 휴대폰에서는 주변 노드를 숨기고 위→아래로 놓습니다.
- **LLM 입력**: `SLIDE_9.llmInput`. 코드 입력처럼 어두운 상자에 `{ "칸 이름": "값", … }` 모양으로 보입니다. 지금 칸은 오개념, 오개념 설명, 정개념, 정개념 설명, 학습 자료입니다.
  - 값은 모두 이름표로 원래 자리에서 가져오므로 보통 고칠 필요가 없습니다.
  - `from`이 그 칸이 채워지는 슬라이드와 하이라이트 색을 정합니다: `card` 11(빨강), `concept` 12(파랑), `resource` 13(초록). 슬라이드 9~10에서는 모든 칸이 빈칸(`""`)입니다.
  - 상자 색은 `index.html` 맨 위 `--code-bg`(바탕), `--code-key`(칸 이름), `--code-str`(값), 하이라이트 색은 `--hl-card`, `--hl-concept`, `--hl-res`입니다.
- **피드백**: `SLIDE_15`. 회색 상자 위쪽에 `summary`(오개념 · 정개념 · 교과서 다시 보기), 구분선 아래에 `text`(피드백 문단)가 차례로 나타납니다.
  - 문단은 오개념 → 정개념 → 교과서 다시 보기 순서의 3문장입니다. `**가**`는 굵게 보입니다.
  - 상자 옆 버튼 글자는 `buttonLabel`입니다. 버튼을 누르면(또는 Enter) 슬라이드 16으로 넘어가 버튼 옆에 틀린 문제(`SLIDE_15.problem`)가 열립니다. 16에서 버튼을 다시 누르면 닫힙니다.
- **색**: `index.html` 맨 위 `:root`(오답 `--wrong`, 정답 `--right`, 고를 때 `--pick` 등)

`main` 브랜치에 push하면 GitHub Actions(`.github/workflows/static.yml`)가 저장소 전체를 GitHub Pages에 올립니다.

1. `data.js`(또는 `index.html`)를 고치고 로컬에서 확인합니다.
2. commit 후 `main`에 push합니다.
3. GitHub 저장소의 **Actions** 탭에서 "Deploy static content to Pages"가 초록색으로 끝나면(보통 1분 안팎) 배포된 주소에서 확인합니다.

배포 때문에 지키는 것:

- **주소는 상대 경로로 씁니다.** 배포 주소가 `https://<계정>.github.io/kgdx-demo/`처럼 하위 폴더라서, `/data.js`처럼 `/`로 시작하면 파일을 못 찾습니다.
- **파일 이름의 대소문자를 정확히 맞춥니다.** Windows는 `Data.js`와 `data.js`를 같게 보지만 GitHub Pages 서버는 다르게 봅니다.
- **`index.html`의 `<script src="data.js"></script>` 줄은 모양을 바꾸지 않습니다.** 배포할 때 이 줄을 찾아 `data.js?v=커밋번호`로 바꿉니다. GitHub Pages는 파일을 10분 정도 캐시해서, `data.js`만 고쳐 push하면 한동안 옛 `data.js`가 보일 수 있기 때문입니다. 저장소의 파일은 바뀌지 않고 배포본에만 적용됩니다. 이 줄을 못 찾으면 배포가 실패하며 알려 줍니다.
- `README.md`도 함께 배포되어 주소 뒤에 `/README.md`를 붙이면 보입니다.

## 실제 시스템과의 관계

원본 프로젝트 `연구및개발설계/kgdx_spec`의 코드와 비교해 점검한 결과입니다.

### 실제와 같은 것

- **판정 단위**: 두 문제는 원본 판정 단위 U1(1-1·1-2, 개념 `변수 값 정하기`)과 같은 개념을 묻습니다. 두 응답을 함께 판정합니다. (`seed/item_sets.csv`)
- **오개념·교과서**: 오개념 카드 MC-VAR-01a(판정 대상 T01)와 교과서 102쪽은 seed 그래프 그대로입니다. 주변의 MC-VAR-01b(처음 값을 기억한다), MC-VAR-10(값 대신 이름이 나온다), 리스트 노드도 seed에 있는 노드입니다.
- **정개념 설명**: 정개념 「변수」(`CPT-VAR`)의 설명 "변수는 이름을 붙인 저장 공간이며, 한 번에 값 하나만 가진다."는 `seed/concepts.csv` 그대로입니다.
- **판정에 쓰는 것**: 고른 답의 종류와 확신도만 씁니다(T3, T3). 문제 글과 고르지 않은 선지는 쓰지 않습니다. (`proto/judgement.py`)
- **판정 규칙**: 두 응답이 모두 표적 오개념이고 한 번 이상 확신했으면 판정표에서 오개념 칸입니다. 이어서 두 답의 오개념이 같은지 확인하고(다르면 판정 유보), 같으므로 오개념으로 판정합니다. LLM은 쓰지 않습니다. (`config/judgement_matrix_long.csv`, `config/rules.json`의 `mc_requires_same_card`)
- **그래프 경로(Q1)**: 선택지 → 카드 → 관련 개념 → 개념 → 설명 자료 → 학습 자료(교과서, 최대 2개) 순서로 찾고, 슬라이드 10~13이 이 순서입니다. (`proto/paths.py`)
- **피드백 다시 쓰기**: LLM 출력이 검사에 걸리면 한 번 더 생성하고, 그래도 안 되면 고정 문장을 씁니다. (`config/feedback_validation.json`)

### 시연에서 다르게 보여 주는 것

- **채점 시점**: 실제 시스템은 학생이 모든 문제를 풀고 제출한 뒤 서버가 한꺼번에 판정합니다. 학생은 풀면서 ✕·✓를 보지 않습니다. 시연은 이해를 돕기 위해 문제마다 채점을 보여 줍니다.
- **선지 → 오개념 선**: 설계 경로의 "지시" 관계입니다. 화면에서는 선 위 글자를 모두 뺐습니다. seed 그래프에는 선지 노드와 이 선이 없고, 선지가 어느 오개념과 연결되는지는 문항 데이터(`seed/items_seed.json` 선지의 `card_id`)에 적혀 있습니다. 시연은 이를 그래프 위에 그려서 보여 줍니다(원본 `proto/demo_case.py`도 같은 방식입니다). 글자를 다시 넣으려면 `SLIDE_9.graph.edges`의 첫 두 줄 `label`에 `"지시"`를 씁니다.
- **문제**: 원본 1-1·1-2(나이·배터리, 계산식 포함)를 계산식 없이 단순하게 바꾼 문제(단어·배터리)입니다. 문제 번호는 1·2로 보여 줍니다.
- **LLM 입력**: 시연은 그래프에서 찾은 근거만 `{ "오개념", "오개념 설명", "정개념", "정개념 설명", "학습 자료" }`로 보여 줍니다. 실제 코드(`proto/llm_feedback.py`의 `_payload_review`, `_state_fields`)는 문항 번호·판정 결과·문제·코드와 카드의 믿음 확인 질문·실행 반례, 개념 이름과 카드의 `correct_conception`을 영어 칸 이름으로 넣고, 오개념 설명(카드의 믿음)·개념 설명(`definition`)·교과서 쪽은 넣지 않습니다(교과서 쪽은 서버가 화면에 붙임). 실제 시스템도 시연처럼 바꾸려면 `_payload_review`와 `_state_fields`를 고쳐야 합니다.
- **오개념 설명**: 카드 MC-VAR-01a의 믿음 「변수는 여러 값을 동시에 가진다(정한 값이 쌓인다)」를 풀어 쓴 문장입니다.
- **피드백**: 문장은 미리 써 둔 것입니다. 오개념 → 정개념 → 교과서 다시 보기 순서로 쓰고 교과서 쪽(102쪽)을 문장 안에 넣습니다. 실제 시스템은 믿음 확인 질문 → 실행 반례 → 정개념 순서로 쓰고, 출력 검사(`config/feedback_validation.json`)에서 쪽 번호를 쓰지 못하게 합니다. 그래서 지금 시연 문장은 원본 검사의 '쪽 번호 금지'에 걸립니다(길이 220자 이하·3문장 이하는 지킵니다).
- **피드백 화면**: 실제 학생 화면처럼 피드백을 먼저 보여 주고, '틀린 문제 보기' 버튼으로 틀린 문제를 여는 모습은 시연용으로 그린 것입니다.
- **채점 표시**: 채점 때는 정답·오답만 표시하고, 고른 답이 어떤 오개념인지는 판정 상자(슬라이드 8)와 그래프에서 처음 보여 줍니다.
- **확신도**: 실제 시스템은 세 단계(확실해요·조금 확실해요·잘 모르겠어요)이지만, 시연은 두 단계(확실해요·확실하지 않아요)만 보여 줍니다. 판정 규칙 문장도 "한 번 이상 ‘확실해요’"로 맞췄습니다.
- **오개념 이름**: 오개념 id 대신 학생 눈높이의 짧은 이름을 씁니다. 이번 오개념 MC-VAR-01a는 「값이 쌓인다」(원본 판정 대상 이름은 T01 「변수 값 누적」), 주변은 「처음 값을 기억한다」(MC-VAR-01b), 「값 대신 이름이 나온다」(MC-VAR-10), 「값이 누적된다」(시연용)입니다.
- **정개념 노드**: seed에서 MC-VAR-01a는 `CPT-VAR-SET`(변수 값 정하기)에 이어져 있지만, 시연은 한 단계 위 개념 `CPT-VAR`(변수)로 보여 줍니다. 그래서 오개념 → 변수 선, 처음 값을 기억한다 → 변수 선은 시연용입니다(원본은 → 변수 값 정하기).
- **주변 노드 중 시연용**: 「값이 누적된다」(문제 2의 ① 230 = 100 + 50 + 80) 카드와 그 선은 원본 seed에 없어 시연용으로 넣었습니다. 「함수」는 seed에서 변수 쪽과 이어진 선이 없어 변수와는 잇지 않았고, 배경 학습 자료로 교과서 118쪽과 이었습니다.
- **문제 2 선지**: ① 230 ② 100 ③ 배터리 ④ 100 50 80 ⑤ 80(정답) ⑥ 그 외의 답, 여섯 개입니다.
- **정개념 칸**: 설계서의 노드 유형 이름(정개념: 성취기준, 개념)에 맞춰 개념 노드를 "정개념"으로 부릅니다(원본 관계 이름은 "관련 개념"이고, 선에는 글자를 쓰지 않습니다).
